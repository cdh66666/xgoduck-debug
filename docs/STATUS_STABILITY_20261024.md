# 星猫调试页状态稳定性修复 · 2026-10-24

用户最新边界：小鸭子在托盘内，保持 OFF、disabled、motion-inhibited；99.9 Hz 这种不影响使用的微小频率差异无需报警，避免状态栏反复闪动。

## 根因与修改

旧页面将同一个 150 ms 帧龄条件用于无线连接、舵机数量、IMU 和卸力文字。一帧晚到导致四项一起变色/清空；新帧到达后又一起恢复。修复前 60 s 实测没有断连，各设备项仍各跳变 198 次。

现在分开显示三种事实：无线项由服务器观察到的通道状态判断；舵机、IMU、扭矩显示明确标注的“最近回报”；旁边独立显示实际反馈年龄。设备回报用中性色，无效采样不会冒充当前硬件故障。浏览器渲染/调度暂停仅使可见数据变老，不能作为 Wi-Fi 断开的证据。服务读失败、服务器证实通道持续无数据、真实舵机缺失/IMU 异常仍明确显示。

舵机数量沿用主控已有的逐轴 150 ms 应答窗口。单次总线漏读、下一次恢复，不计为设备失联；某轴在主控侧实际持续失去应答则显示缺失。计算主控侧年龄时扣除电脑传输/缓存所加的年龄；无线晚到仍单独显示，不伪造为全部舵机掉线。

电压采样会占用一个电流采样时隙。此时使用带时间的最近完整电流实测值，源端年龄达到 150 ms 就不再用该值补充；不求和残缺数据、不补零、不改动原始记录。收到的真实电流数值仍正常变化。

控制资格仍每帧按原有 150 ms 阈值检查，失鲜后暂停新的运动输入；真实模式变化不等待确认窗口。姿态仍立即显示最新实测端点，没有增加显示缓冲、平均或预测。设备历史回报不能作为启动控制许可。全程未发送硬件写请求，未进行运动测试。

## 同条件实测

两次各采集 60 s，使用同一台电脑、同一 AP、同一托盘卸力状态。页面几何加载后前 2 s 排除。以下“跳变”指设备文字/状态变化，电流数字的正常变化不计入故障跳变。

| 项目 | 修复前 | 修复后 |
|---|---:|---:|
| 无线状态跳变 | 198 | 0 |
| 舵机回报状态跳变 | 198 | 0 |
| IMU 回报状态跳变 | 198 | 0 |
| 扭矩回报状态跳变 | 198 | 0 |
| 页面姿态已知年龄中位数 | 71.2 ms | 70.3 ms |
| 页面姿态已知年龄 P99 | 261.9 ms | 221.4 ms |
| 硬件写请求 | 0 | 0 |

本轮修复显示语义，没有修改传输或控制时钟，因此不将两次网络时延波动宣传成传输性能提升。数据年龄仍有可见波动，不能宣称无线绝对零抖动。

19 组相关 JavaScript 测试通过，其中工作台包含 331 个断言。覆盖 149/151/80/180 ms 来回波动时设备回报不闪、控制资格即时失效、真实掉一颗舵机/IMU 故障立即显示、浏览器暂停不冒充无线断连、通道中断明确提示、电流缺帧及源端过期。

公开测量摘要：`firmware-support/validation/status-stability-20261024.json`。本机原始数据和前后截图：`pc/qa/status-stability-20261024/`。主控、固件和运动锁均未改动。

## 后续修复：模型内重复提示闪烁

用户继续指出仍有一个元素闪烁。实际定位到模型左上角“反馈延迟 · 保留姿态 / 接收间断 · 保留姿态”，此前顶部状态栏修复没有覆盖 iframe 内这套提示。模型 CSS 仍随 150 ms 边界切换提示的显隐。

工作台明确指定由父页面承担接收时效显示。仅在模型已加载、未发生模型错误、处于实时/短时延迟/缺帧模式时，移除这处重复叠加提示。顶部真实反馈年龄及设备回报、底层失鲜标记、150 ms 控制门限均保留；加载、模型错误、图形上下文丢失、暂停、回放和独立模型页面仍显示各自提示。

20 秒只读浏览器实测：提示显隐切换 81 → 0 次。修复后仍采到 69 个超过 150 ms 的样本，证明结果并非因为这次网络刚好完全稳定。顶部说明和记录器文字均无跳变；无 JavaScript 错误、无硬件写请求。10 项实际 CSS 状态验证通过，9 组相关 JavaScript 测试通过（工作台 331 个断言）。末次读取仍为 OFF、disabled、motion-inhibited。

测量摘要：`firmware-support/validation/status-banner-20261024.json`。此修复没有增加缓冲，也不宣称无线抖动消失。
