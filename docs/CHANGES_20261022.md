## 为什么仍会“断连/停机”

必须区分：无线TCP连接存活、姿态新鲜、控制命令有回执、本地主控仍上力。现在界面能显示“状态延迟”，而真正命令失联仍会保护卸力。页面隐藏、控制POST失败或本地传感器失效也会退出控制。

本机曾测到普通静置窗最大约0.83–1.01秒接收空档，定向抓包观察时还出现2.85秒空档；后一窗带系统跟踪，不能当普通性能基准。网卡“数据包合并”开→关→恢复的P95约188/188/219ms，没有稳定收益，参数已恢复。PktMon两次文件实际没有包，不能拿空捕获判定卡在网卡前或应用后。

因此，**现有证据不能认定是这台电脑网卡，也不能保证换电脑就解决**。换机是合理对照，可保持同一鸭子/固件/模型/网络，只比较两台电脑收到真实新帧的间隔与控制回执，避免同时修改模型和网卡造成混淆。

## 仍然没通过的事情

持续自主站稳、起身后不后撤、实物走停、任意跌姿恢复以及翻滚供电问题都没有新的通过结论。最近一次测试只留下请求意图和后续 `shadow / web heartbeat lost` 状态，没有完整本地动作回放，不能说那次动作成功，也不能据此分析后撤的完整过程。

旧版本可在Git历史查看，不改写或强推历史。本次不借迁移继续试机器人，不更改其校准、PD、固件或模型运行目标。
