# 官方控制对照与当前默认模型

已恢复官方 Walk，并让实机和调试台模型预览使用官方共享22°参考姿态与0.2头部滤波。新的默认模型在鸭子本地运行；独立训练目录、47500检查点和机械校准均保留。

官方`proc.py`与原调试台轴向适配一致，没有发现需要翻转IMU轴的证据。模型比较仍保留已验证的静止陀螺偏置校正、直接起身、当前MCU时钟和传感采样修复；策略数学对齐不代表整个控制栈字节等同官方。

## 实机记录

- 最新完整官方程序先有一轮18秒试验起身后再次进入恢复，后来一轮20秒试验在起身后连续约17.8秒保持Walk控制。初始姿态不同，不能用这两轮给模型排名。
- 在原调试台里只替换ONNX文件的一轮20秒试验，起身后连续约16.9秒运行Walk，没有再次恢复，连续采样约15.6秒倾角小于15°。旧适配器会同时采用该文件metadata的约24°HOME，因此这并非固定输入输出映射下仅换神经网络参数。
- 对齐官方共享HOME与滤波后的一轮20秒试验，起身后连续约19.0秒运行Walk，没有再次恢复；后段连续采样约18.6秒倾角小于15°。两轮上力期间均15轴在线，结束均为新鲜OFF/disabled。
- 对44组已记录实机状态，当前Walk/Get-up适配器与固定官方源码的观测向量、输出目标逐值相同。它只证明计算一致，不能替代实机测试。
- 原调试台回接后，通过它的实际控制API完成起身、W等价的0.2前进指令、松键等价零速和OFF。板端连续5个观测收到前进命令，随后19个policy零速观测约1.14秒仍处于Walk，倾角5.1～13.5°，最后确认卸力；全程15轴有效。此前20帧/1.18秒的统计含一帧OFF-but-enabled过渡。没有独立测量位移、速度或直线性。浏览器键盘/停止逻辑另有268项离线检查，未占用用户键鼠。
- 曾在Get-up尚未结束、颈部仍快速运动时提前切固定Hold，随后后倒；该轮不能证明稳定站立后固定姿态也会倒，未用于认定零位错误。
- 历史`9dc3678`全套候选烧录后没有任何反馈，未发送上力；恢复最新官方版本后通信恢复。这不是旧版站立失败的证据。原版本、失败日志和回滚记录均保留。

早先把恢复过程的大倾角误报成“只换官方Walk仍失稳”，已按完整阶段记录纠正。当前结论是恢复官方模型后观察到持续站立，不能从初始状态不同的有限试验锁定唯一物理根因，或宣称任意跌姿、受推恢复和六档走停都已通过。

用户随后再次报告点击站立后向后倒。因此17～19秒是当时有限窗口的结果，站立稳定性继续OPEN。最近原始反馈文件中找回两段约10.67秒/7.51秒上力数据，按时间关联到用户报告，具体点击未绑定；原始加速度不能补写成当时滤波姿态，记录期望角也不能当成裁剪后总线raw goal。两段与此前5条实机抓取已加入历史回放，缺失字段和估算层分别标识。
