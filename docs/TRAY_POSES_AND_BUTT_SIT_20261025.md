# 托盘、姿态按钮与臀部落座模型交接

## 当前实机边界

用户拿出托盘试过两个按钮，发现回正也在站立。随后为安装修复，用户明确回复“已放回托盘并卸力”。最新读回 OFF、enabled=false、tray_motion_guard.detected=true。不能执行回正、站立或坐下动作。安装只执行卸力和版本读回，未执行任何上力验证。15/15 中位校准未重复写入。

## 界面修复及证据

- 常态为“回正”“站立姿态”；托盘姿态把整个按钮组替换为高亮的“托盘内 · 动作已锁定”。托盘判定和维护文件锁分别处理；动作准入仍受两者约束。
- 原来 `sequence-toggle.disabled` 错误绑定 `motion_inhibited`，导致恰好在应校准的托盘内打不开校准窗口。已解除这个错误关联，窗口打开只读；保存中位仍须用户点击确认。当前固件支持全程卸力校准，已同步更正文案。
- 状态栏正常读数统一蓝色；实际故障仍区分显示。
- 旧参数核对错误要求 `default_pose_s==0`，当前官方程序为 1 秒。现在核对当前官方部署的 50 Hz、HOME、motor-order default 与 encoder center；这是参数匹配，不冒充运行二进制身份。程序身份独立由固件面板验证。
- 用户拿下后仍灰的原因是旧 `data/motion-inhibit` 文本“neutral calibration tray/charging ... recalibration pending”。在用户明确要求恢复按钮、实时反馈非托盘且 OFF 时，只删除了这一已完成校准的旧锁；未发送动作。证据 `obsolete-tray-lock-cleared.json`。实时托盘保护不会随它删除。
- 按钮每次反馈跨过 150 ms 就变灰，实际 5 秒观察 17 次亮灰切换。改为预告按钮的显示容忍短暂抖动，连续 2 秒无有效报告才禁用；点击确认仍严格检查 150 ms 新鲜反馈，板端也独立准入。修复后同长度实测 0 次切换，0 POST。证据 `pose-flicker-before.json` / `pose-flicker-after.json`。真实用户页面已刷新。
- JS 行为测试 341 项、回正/托盘专项 33 项、校准流程 27 项通过。真实连接只读打开校准窗口，未写零位或启动电机；空地显示分支使用隔离浏览器响应夹具验证。

## 回正与站立确实分开

漏查发生在部署边界：仓库自定义控制器的 hold 已发零度，但实机官方拆分控制器的 `step()` 仍回退到 `policy.default_deg`。页面两个 API mode 不同，不能证明最终角度不同。用户实测后读回 hold 的 15 轴目标为站姿，复现明确。

从实际设备下载控制器并核对原指纹 `f364daf44bbfeb5d0f00ddff8fd5e1867ee69f6b44d4a687d48e768449fc6946`，只修改 hold 的 15 轴目标和嘴部目标为 0；policy 仍原模型，ARM 首包仍当前测量角度。`pc/pose_contract_check.py` 执行该实际 `step()` 并解码真实 wire 包，旧源码失败、新源码通过；同一源的 50 Hz 时钟测试通过。不能再只核对网页标签或仓库另一套控制器。

已安装 `2026.10.25-neutral-r2`，新启动控制器 SHA256 为 `0de772cf8d1812f26937402367f933f8a4c5c8387f5df86431dac272a2a0c8f4`；运行版本核验 true。MCU 未改动，仍 `20261025-feedback-r1` / ELF `770e412fcb93af129892e462c5670a61ff3216640cdf6ea279c30861680eeeb2`。

安装任务 `bcbc66beb5224be4b4abab859652abed` 为 `installed_off_verified`，保留校准与所有模型。候选位于板端 `.codex-stage/neutral-hold-20261025-r2`，本地实际源码 `pc/qa/post-calibration-20261025/neutral-native`。`pc/firmware_install_remote.py` 已允许清单中明确列出的控制器更新，正确验证新指纹，其余受保护文件仍核对原哈希。实机当前为 OFF，不把离线目标检查称为实机回正验收。

## 新坐下模型：仅仿真

- 新入口 `training/train_butt_sit.py`，使用 `training/butt_sit.py`、同一 826 g 原生物理模型、BAM 电机、200 Hz 物理、100 Hz 反馈和每 20 ms 一次 ONNX 推理。
- 旧 V2 目标只低蹲；同条件结束时后壳仍离地 17.84 mm、臀部力 0 N。新 V3 指定后壳 `r5_cover_collision` 接地、双脚在前，不靠 root 高度推断坐成功。
- 直接插值到静态坐姿会因后仰角速度翻倒。原生闭环示教加入俯仰角速度阻尼后，再训练专用相位/IMU actor；64/64 示教场景通过，32/32 未参与训练的独立场景通过。随机电压 7.2–8.1 V、摩擦 0.55–1.0、初始倾角约 ±2°、关节 ±0.7°。没有验证这个范围之外的扰动。
- 32 轮首次臀部接地 1.08–1.10 秒，最低头部离地 96.13 mm；最后 2 秒持续臀部承重，最大平均残余位移速度 0.396 mm/s。示例 1.10 秒接地、1.66 秒起满足连续 0.5 秒收稳门槛。落座中有短暂双脚离地，保留原始回放，未剪掉过渡。
- 同条件示例后段臀部约 3.75 N、双脚约 4.36 N。接触位置与力来自 MuJoCo；绿色点为实际臀部接触点。碰撞接触数值容许约 0.1 mm 量级穿透。没有据此宣称打印件结构强度或实物动作已通过。
- 新权重 `training/outputs/sit-policy-20261025/butt-v3/sit-butt-v3.onnx`，SHA256 `827a61364899104e15615a3aec46b70f73b38aa93384e4ed26f3a581ef2f1cff`。仅 sit-only、相位索引 55 / 1 秒，后段需持续调用保持。没有训练起立方向。
- `sit-butt-v3.mp4` 为 1× 原生物理回放，`five-frames.png`、`before-after.png`、`comparison.json`、`result.json` 和 `summary.json` 同目录。仿真每秒 50 次推理是仿真时间；电脑 ONNX 最大单次约 1.08 ms，不是实机 Linux 调度保证。
- 尚未部署新坐下模型，实机仍为 V2 `xgoduck_sit.onnx`。后续部署前必须适配新 1 秒相位与约 −24° 终态，不能沿用 V2 的 8.5 秒时长/20° 倾角门槛。先让用户看仿真，再在新的实机授权下验收；不得在托盘测试。

现场只允许读回。不要为了展示 50 Hz 而在托盘启动推理或电机。
